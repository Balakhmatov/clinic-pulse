# Бизнес Пульс — инструкция для салонов красоты

Версия описания: 10 ноября 2026 года. Описана текущая демонстрация с денежной оценкой окон, отклонений и рейтингом мастеров.

**Открыть:** https://balakhmatov.github.io/clinic-pulse/salon/

## 1. Для чего предназначен сервис

Сервис показывает загрузку мастеров, свободные окна, результаты администраторов, возвращаемость клиентов и экономику услуг. Администратор может подобрать клиентов под окно, подготовить сообщение, сохранить результат контакта и создать запись.

Демо работает без авторизации и сервера. Реальные рассылки, YCLIENTS, Altegio и другие системы записи **не подключены**. Файлы обрабатываются в браузере; сообщение нужно отправить самостоятельно в рабочем канале.

**Хранение:** изменения существуют до обновления страницы. Для сохранения всей сессии используется JSON; Excel — отчёт и таблица визитов, не полная резервная копия.

## 2. Быстрый старт

1. Откройте «Обзор салона»: демоданные уже заполнены. Расчётная дата — **10 ноября 2026 года**, она фиксирована и не следует автоматически за календарём.
2. В «Окнах и записях» выберите дату, мастера и администратора.
3. Нажмите подходящее окно, затем выберите услугу и клиента.
4. Через «Контакт» подготовьте текст и отметьте результат; через «Записать» создайте запись.
5. После визита откройте «Изменить» у записи и укажите итоговый статус.
6. Посмотрите пересчёт KPI и планов. Сохраните сессию: «Данные и интеграции» → «Сохранить всю демку · JSON».

«Восстановить демо» возвращает исходный демонстрационный набор. Несохранённые изменения заменяются.

## 3. Что находится в разделах

| Раздел | Содержание |
|---|---|
| Обзор салона | Выручка, вклад, загрузка по записям, окна на расчётную дату, динамика и команда |
| Окна и записи | Свободное время, подбор клиентов, контакт, новая запись и статусы визитов |
| Администраторы | Обращения, попытки, диалоги, записи, конверсии, доходимость и результаты работы с окнами |
| Мастера | Экономика, загрузка, переделки, задержки и возвращаемость |
| Услуги и экономика | Итоги по услугам и редактирование их параметров |
| Планы и результат | Личные цели администраторов и мастеров, выполнение и нужный дневной темп |
| Данные и интеграции | Шаблон, импорт визитов, Excel-отчёт, JSON и справочники ID |

Верхние даты определяют период большинства отчётов. Окна и расписание используют **собственную дату внутри раздела**. Планы всегда считаются за **свой период**. Фактические завершённые визиты учитываются не позже расчётной даты `asOf`.

## 4. Выручка и экономика

В расчёт экономики входят только визиты со статусом **«Визит состоялся»** (`completed`). Запись сама по себе ещё не выручка.

| Показатель | Формула / смысл |
|---|---|
| Чистая выручка визита | Цена − скидка − возврат |
| Выплата мастеру | Чистая выручка × процент мастера / 100; округляется до рубля по каждому визиту |
| Материалы | Прямой расход материалов на визит |
| Прочие | Другие прямые расходы визита |
| Вклад | Чистая выручка − выплата мастеру − материалы − прочие расходы |
| Вклад за час услуги | Вклад / (длительность оказанных услуг в минутах / 60) |
| Средняя сумма визита | Чистая выручка завершённых визитов / их количество; доступна в расчётной модели, отдельной плитки в интерфейсе сейчас нет |

Пример: цена 3000 ₽, скидка 200 ₽, возврат 300 ₽ → выручка 2500 ₽. Комиссия 40% = 1000 ₽, материалы 300 ₽, прочие 50 ₽ → **вклад 1150 ₽**.

Вклад рассчитан **до аренды и других постоянных расходов**. Это не чистая прибыль салона. Расчёт часа использует длительность услуги, без технического буфера.

Если материалы, комиссия или прочие расходы неизвестны, показывается «—» для вклада и итогов соответствующих расходов. **Пусто — неизвестно; 0 — расхода нет.** Выручка при этом может быть рассчитана.

На обзорном графике показаны дни выбранного периода, максимум первые 31 день; это ограничение текущей визуализации.

## 5. Загрузка и свободные окна

Доступное время = внесённые смены мастеров минус перерывы. Наложившиеся занятые интервалы объединяются, чтобы не считать одно время дважды.

| Показатель | Расчёт |
|---|---|
| Загрузка по записям | Занятое время вместе с буфером / доступное время смен × 100% |
| Фактическая загрузка | Время завершённых услуг без буфера / доступное время × 100% |
| Свободное окно | Непрерывный остаток времени смены после перерывов и активных записей |
| Подходящая услуга | Мастер её выполняет, а длительность + буфер помещаются в окно |

Отменённая запись освобождает окно. Неявка сохраняет исторически занятый интервал в загрузке по записям, но не добавляет фактическую работу и выручку. Поэтому «загрузка по записям» и «факт» различаются.

Пример: смена 9 часов минус 30 минут перерыва = 510 минут. Записи заняли 300 минут с буферами → **58,8%**. Завершённые услуги длились 240 минут → фактическая загрузка **47,1%**.

Расчёт опирается только на внесённые смены. Отсутствующая смена не создаётся автоматически. В демо смены заполнены на 1–11 ноября.

## 5.1. Сколько денег находится в свободных окнах

На главной плитка **«В свободных окнах — до … ₽»** показывает сумму максимальных сценариев заполнения всех подходящих окон на расчётную дату. Ниже блок **«Незаполненные окна — деньги в расписании»** выводит первые три окна с суммами и кнопкой «Подобрать»; все окна доступны в «Окнах и записях».

Для каждого окна рассчитываются сценарии по услугам, которые выполняет мастер:

1. Вместимость одной услуги = целая часть от `длительность окна / (длительность услуги + буфер)`.
2. Стоимость такого сценария = вместимость × цена услуги.
3. Нижняя граница — минимальная выручка среди сценариев повторения одной подходящей услуги.
4. Верхняя граница — максимальная выручка от помещающейся комбинации подходящих услуг; можно сочетать разные услуги.

Например, окно 210 минут: маникюр 90 + 15 минут, 2400 ₽ → два визита, 4800 ₽. Педикюр 100 + 15 минут, 3200 ₽ → один визит, 3200 ₽. Оценка окна **3200–4800 ₽**. В другой ситуации более короткая услуга может дать больше посещений; количество не фиксируется заранее.

Это диапазон **сценариев заполнения**, не гарантированный доход, не универсальный минимум и не подтверждённые потери. При отсутствии клиентов доход может остаться нулевым. Оценка идёт по прайсу до скидок, комиссий и расходов. Перерывы и буфер учитываются; неподходящие мастеру услуги исключаются. Рейтинг клиентов не превращается в обещание заполнить все окна.

При создании записи занятое время вычитается, и потенциал оставшихся окон пересчитывается. Для прошлого дня оценка описывает незанятую мощность расписания, а не сумму подтверждённого ущерба.

## 6. Как заполнять окно

1. Выберите дату, мастера и ответственного администратора.
2. Выберите окно и подходящую услугу.
3. Посмотрите список кандидатов: сначала лист ожидания, затем недавняя отмена, затем наступивший срок повторной услуги. У клиента показаны до трёх последних завершённых визитов: услуга, дата и сумма после скидки/возврата.
4. Через «Контакт» скопируйте или отредактируйте текст; отправьте его самостоятельно. Сохраните «Нет ответа», «Состоялся диалог», «Связаться позже» или «Отказ».
5. При согласии нажмите «Записать», проверьте дату/время и скидку.
6. После визита измените статус на состоявшийся, отмену или неявку; при необходимости внесите расходы, возврат, задержку и переделку.

Учитываются разрешение на контакт, отказ от контактов, предпочтения по мастеру/времени и занятость клиента. Клиенты с будущей записью на ту же услугу исключаются. Недавние исходящие попытки менее трёх дней назад ограничивают повторный контакт; открытый диалог и просьба связаться позже оставляют возможность продолжить работу.

Время подбора — начало выбранного окна. Программа не перебирает автоматически все варианты начала внутри него. При сохранении записи повторно проверяются вместимость окна, услуги мастера и пересечение с другими записями клиента.

**Важно:** «Скопировать текст» не отправляет сообщение. «Результат контакта» фиксирует действие администратора внутри демонстрации.

## 7. KPI администраторов

Основа — **обращение**, а не каждая попытка звонка. Один клиент может иметь несколько отдельных обращений. Входящие и исходящие разделены.

| Показатель | Как считается |
|---|---|
| Входящие / исходящие | Количество обращений соответствующего типа |
| Попытки | Сумма попыток связи по обращениям |
| Диалоги | Обращения, где отмечен состоявшийся диалог |
| Записи | Связанные с обращениями визиты, кроме отменённых; одно обращение может дать несколько записей |
| Входящие → запись | Входящие обращения с хотя бы одной неотменённой записью / все входящие обращения |
| Исходящие → запись | Аналогично для исходящих |
| Диалог → запись | Диалоги с неотменённой записью / все диалоги |
| Доходимость | Завершённые связанные визиты / все связанные визиты, дата которых наступила |

Обращения отбираются по **дате создания обращения**, администратору и периоду отчёта. Сами связанные визиты могут быть позже этого периода. Будущие визиты не входят в знаменатель доходимости. В текущей формуле наступившие отмены и неявки входят в знаменатель.

Пример: 20 исходящих обращений, 35 попыток, 10 диалогов, 6 обращений привели к записи → исходящая конверсия **30%**. Если эти шесть обращений дали восемь визитов, число записей — 8, но конверсия всё равно 6 / 20.

Повторные исходящие контакты одного администратора с тем же клиентом, источником и датой создания объединяются в одно обращение с ростом числа попыток.

### Работа с окнами

- **Окон заполнено** — новые неотменённые записи из сценария окна, без помеченных переносов.
- **Часов записано** — длительность этих услуг + буферы, переведённые в часы.
- **Вклад состоявшихся визитов** — вклад завершённых визитов из окон, отобранных по администратору и дате создания визита в периоде.

Это разные основания отбора: основные конверсии — по дате обращения, денежный результат окон — по дате создания визита. Импорт без связи с обращением не восстанавливает воронку администратора.

## 8. KPI мастеров и возвращаемость

У мастера показываются выручка, вклад, вклад/час, визиты, загрузка по записям и факту. Переделки считаются по завершённым визитам с отметкой; доля = переделки / завершённые визиты. Задержки — число завершённых визитов с опозданием **более 10 минут**.

Возвращаемость считается по новым клиентам:

1. По всей доступной истории находится первый завершённый визит клиента в салон.
2. Для выбранного мастера берётся группа первых визитов за период, **сдвинутый на 30 дней назад** относительно фильтра.
3. Для каждого клиента срок ожидания равен «Циклу повторной услуги» его первой услуги.
4. В знаменатель входят только клиенты, у которых этот срок уже истёк к расчётной дате.
5. Проверяется, был ли последующий завершённый визит на более позднюю дату до конца срока: к тому же мастеру и к любому мастеру салона отдельно.

Повторный визит может быть на другую услугу. Это возвращаемость клиента, не повтор именно той же процедуры.

Пример: из 10 новых клиентов срок истёк у 6. Четверо вернулись в салон, трое — к тому же мастеру → **66,7% в салон**, **50% к мастеру**. Четверо незрелых клиентов пока исключены.

Неполная история может ошибочно представить постоянного клиента новым. Сейчас срок возврата берётся из текущего справочника услуги; его изменение может пересчитать историческую возвращаемость. Точный период и число ожидающих клиентов подписаны под каждым мастером.

## 9. Планы и адаптивный темп

Нажмите «Добавить план»: роль, сотрудник, показатель, период, цель. Можно изменить или удалить план. Пересекающиеся планы одного сотрудника по одному показателю запрещены.

**Администратор:** исходящие контакты, записи, входящая/исходящая конверсия, конверсия диалогов, доходимость.

**Мастер:** выручка, проведённые визиты, вклад, возвращаемость к мастеру.

| Показатель | Формула |
|---|---|
| Выполнение | Факт / цель × 100% |
| Остаток | max(0, цель − факт) |
| Нужный дневной темп | Остаток / календарные дни после расчётной даты до конца периода |

Цель 90 записей, факт 50, осталось 20 дней → нужно по **2 записи в день**. Факт вырос до 70 → по **1**. Цель периода не меняется. После выполнения остаток и темп равны нулю. Для процентных целей дневной темп не рассчитывается. При неизвестном факте — «—».

Сейчас используются **календарные дни**, без индивидуального рабочего календаря. Темп — рекомендация на оставшийся период, не отдельная история дневных заданий. Планы не обязаны брать цели из системы записи: они уже вводятся вручную и сохраняются в JSON.

## 9.1. Деньги сверх темпа и недобор

В личных планах мастеров по выручке и вкладу выводится денежное отклонение **от планового темпа к расчётной дате**, не от всей цели месяца.

`Ожидалось к дате = цель × прошедшие календарные дни / все календарные дни плана`.

`Денежное отклонение = накопленный факт − ожидалось к дате`.

Пример: цель 180 000 ₽ на 30 дней, расчётная дата — десятый день. Ожидалось 60 000 ₽. Факт 71 200 ₽ → **+11 200 ₽**. Это опережение темпа; оно ещё не означает выполнение всей месячной цели. Факт 50 000 ₽ → **−10 000 ₽** к темпу.

Для плана количества визитов разница в посещениях переводится в рубли через среднюю чистую выручку завершённого визита этого мастера за период к дате. Такая сумма отдельно подписана как **оценка по среднему чеку**. При отсутствии завершённых визитов денежной оценки нет. Процентные KPI и планы администраторов автоматически в рубли не переводятся: их денежный результат доступен отдельно в работе с окнами.

## 9.2. Рейтинг на главной

Блок **«Кто опережает план, где недобор»** показывает:

- До двух мастеров с наибольшим положительным отклонением выручки от темпа.
- До трёх мастеров с наибольшим отрицательным отклонением.

Используются действующие на `asOf` личные планы **выручки** и их собственные периоды. Верхний фильтр отчёта на этот рейтинг не влияет: дата и основание подписаны в самом блоке. Мастера без действующего плана не участвуют. Если у мастера неоднозначно несколько действующих планов выручки, он исключается из рейтинга с указанием количества таких случаев. В пустой группе показывается сообщение, а не выдуманный участник.

Рейтинг отражает денежное отклонение, а не причину недобора: загрузка зависит и от спроса, расписания и работы администратора. Положительное отклонение выручки не равно дополнительной чистой прибыли.

## 10. Параметры услуг

В «Услугах и экономике» → «Изменить» доступны название, цена, длительность, буфер, материалы, комиссия мастера и цикл повторной услуги.

Новые записи используют новые условия. Цена, длительность и расходы уже существующих визитов хранятся отдельно и автоматически не заменяются. Визит можно исправить через расписание. Цикл возврата — исключение: для возвращаемости он читается из текущего справочника.

Отдельных экранов создания/редактирования клиентов, мастеров, администраторов, смен и листа ожидания сейчас нет. Эти данные можно перенести и настроить через полный JSON.

## 11. Импорт визитов из Excel / CSV

1. «Данные и интеграции» → «Скачать Excel-шаблон».
2. Заполните **первый лист «Визиты»**. Второй лист содержит справочные ID.
3. Сохраните `.xlsx` или UTF-8 CSV с разделителем `;`/`,`.
4. Нажмите «Загрузить визиты · Excel / CSV».

В отличие от клиники, здесь **нет выбора листа и сопоставления полей**: читается первый лист, названия колонок должны совпадать с шаблоном. Файл — до 16 МБ, до 5000 строк данных на лист. Для дат используйте текст `ГГГГ-ММ-ДД`, для времени — текст `ЧЧ:ММ`; не полагайтесь на числовые даты/время Excel. Десятичные числа в CSV — с точкой.

| Колонка | Что указывать |
|---|---|
| id | Постоянный уникальный ID визита |
| date / start | Дата `2026-11-10`, время `13:30` |
| clientId / masterId / serviceId | ID клиента, мастера и услуги из существующих справочников |
| status | `scheduled`, `completed`, `cancelled`, `no_show` |
| price / discount / refund | Цена до скидки, скидка и возврат, в рублях; скидку/возврат без значения указывайте 0 |
| materials | Материалы: сумма или пусто, если неизвестна |
| commissionPct | Процент мастера, 0–100, или пусто |
| otherCost | Другие прямые расходы: сумма или пусто |
| duration / buffer | Минуты услуги и подготовки; duration больше нуля, buffer неотрицательный |
| adminId | ID ответственного администратора; обязателен |
| contactId | Необязательная колонка/значение: ID существующего обращения того же клиента и администратора |

Все перечисленные заголовки, кроме `contactId`, обязательны. Числовые суммы должны быть неотрицательными; скидка + возврат не больше цены. Завершённый визит с датой позже `asOf` отклоняется. Неизвестные ID нужно сначала добавить в полный JSON: импорт визитов сам справочники не создаёт.

Пример строки CSV:

```csv
id;date;start;clientId;masterId;serviceId;status;price;discount;refund;materials;commissionPct;otherCost;duration;buffer;adminId;contactId
visit-001;2026-11-10;13:30;c48;m1;manicure;scheduled;2400;0;0;300;45;0;90;15;a1;
```

Совпавший `id` обновляет существующий визит; новый добавляется. Дубликаты ID внутри файла запрещены. При ошибке ни одна строка файла не применяется. **Демо при Excel-импорте не очищается автоматически**: данные объединяются по ID.

При импорте `createdAt` устанавливается равным дате визита, источник — `import`, отметки переделки/задержки сбрасываются. Они не входят в Excel-шаблон. Сам импорт не проверяет все конфликты расписания так, как форма новой записи; он предназначен для подготовленной выгрузки. Без `contactId` визит попадёт в экономику мастера, но не в основные конверсии администратора.

## 12. JSON: сохранение всей сессии

«Сохранить всю демку · JSON» выгружает данные и настройки. «Открыть JSON» заменяет текущую сессию целиком после проверки. Ограничение — 8 МБ, до 10 000 записей в каждой таблице.

| Ключ JSON | Содержание |
|---|---|
| version / asOf | Версия формата `1`, расчётная дата |
| masters / admins | Мастера с перечнем допустимых услуг и администраторы |
| services | Условия услуг и циклы повторов |
| clients | Клиенты, разрешения на контакт и предпочтения |
| shifts | Смены и перерывы |
| appointments | Визиты со статусами, ценами и расходами |
| contacts | Обращения, попытки и результаты |
| waitlist | Лист ожидания по услугам, датам и времени |
| goals | Личные планы |
| expenses | Зарезервированное поле; расчёт постоянных расходов сейчас не реализован |

Для своей структуры начните с выгруженного JSON, сохраняйте связи по ID и сначала проверьте изменения на копии. Перенос расчётной даты меняет зрелость возвратов, доходимость и дневной темп. Сам JSON может содержать данные клиентов — храните выгрузку соответственно её содержимому.

## 13. Excel-отчёт

Кнопка «Выгрузить отчёт» создаёт листы «Мастера», «Администраторы», «Планы», «Визиты», а также «Окна в рублях» и «Деньги планов». Показатели мастеров/администраторов и визиты используют выбранный период; планы оцениваются за собственные периоды. Денежные окна относятся к расчётной дате; «Деньги планов» содержит факт, ожидаемый факт к дате и отклонение в рублях.

Лист «Визиты» можно импортировать обратно. Остальные листы — результаты расчётов, не импорт справочников и планов. Для полного восстановления, включая контакты, расписание, настройки и цели, используйте **JSON**.

## 14. Что требует дальнейшего подключения

Автоматические события из системы записи должны передавать постоянные ID визитов, клиентов, сотрудников, услуг и обращений; даты создания и выполнения, статусы, цены/расходы, смены и связи с источником записи. Отмена и повторное получение события должны обновлять существующий ID.

Планы остаются самостоятельными настройками Бизнес Пульса. Массовое назначение и отдельный Excel-импорт планов можно расширять независимо от подключения системы записи. Сейчас эти операции доступны через формы отдельных планов и полный JSON.
