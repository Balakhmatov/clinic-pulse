# Бизнес Пульс — клиника

Отдельная статическая демонстрация без авторизации. Исходный Бизнес Пульс и его production/stage не изменяются.

## Возможности

- Загрузка врачей: дневной план, записи на вчерашний вечер, записи на утро, проведённые приёмы, общая взвешенная загрузка.
- Фильтры по периоду, дате и врачу; интерактивная динамика, свободные места, оценка выполнения плана периода.
- Маршрутизация: направивший врач → специальность/услуга → направлено → записалось → дошло. Агрегированный когортный учёт без персональных данных пациентов.
- Ввод и редактирование строк; XLSX и CSV с выбором листа и сопоставлением столбцов; скачиваемый шаблон.
- Excel-выгрузка обеих таблиц и сводки за выбранный период. Выгрузки совместимы с повторным импортом.
- Данные существуют только в памяти вкладки. Перезагрузка возвращает демо. При первой загрузке своих данных обе демонстрационные таблицы очищаются; следующий импорт другого раздела сохраняет собственные данные первого.
- МИС не подключена; раздел описывает данные, необходимые для будущего подключения.

## Формулы

Загрузка на утро = сумма утренних записей / сумма дневных планов × 100%. Нулевой план означает неопределённый процент. Факт посещений хранится отдельно от записей. Пустой факт не подменяется нулём.

Оценка периода = план периода × проведённые приёмы по строкам с известным итогом / план этих же строк. Для месячного прогноза нужны планы на весь месяц. Демо содержит 1–9 ноября 2026 года.

Конверсия направлений = число состоявшихся визитов / число направлений, выданных в выбранный период. Новые направления могут ожидать визита. Количества этапов должны удовлетворять условию: дошло ≤ записалось ≤ направлено. Обновления той же даты/врача/направления заменяют прежний снимок.

## Запуск

Любой статический HTTP-сервер с корнем репозитория. Node.js нужен только для проверок: `node --test core.test.mjs`.

## Проверки

Проверены взвешенные расчёты, неизвестные факты, некорректные даты и количества, обновление направлений без удвоения. Excel, сформированный встроенным экспортом, открыт через openpyxl. В браузере проверены загрузка страницы, раздел маршрутизации и запуск экспорта. Сквозная проверка загрузки файла в браузере заблокирована разрешением на upload.

Чтение XLSX/CSV адаптировано из management/public/import.js репозитория Balakhmatov/business-pulse.

## Планы по маршрутизации

В разделе маршрутизации доступна кнопка «Поставить план»: направивший врач, направление (врач/специальность/услуга), даты начала и окончания, целевое число выданных направлений. План можно изменить или удалить; факты при удалении не меняются. Пересекающиеся планы для одного и того же маршрута запрещены во избежание двойного счёта.

Таблица показывает план, факт выданных направлений, выполнение в процентах, остаток или перевыполнение. Карточка суммирует планы, пересекающие выбранный период и соответствующие фильтру врача. Каждый план оценивается за свой полный период, указанный в строке; фильтр не обрезает цель. Если по маршруту нет фактов, показывается прочерк, а не подтверждённый ноль. Конверсия направлений в запись и посещение остаётся отдельным показателем.

В Excel добавлен лист «Планы направлений» с целями и результатами. Планы пока вводятся через форму; импорт этого листа не реализован. В демо заполнено шесть планов. Плановые настройки, как и факты, существуют до обновления страницы.

## Интерфейс

Светлый минималистичный интерфейс без фоновых карточек, с линейными SVG-иконками и адаптацией под узкие экраны. Экран «Обзор» объединяет текущую загрузку, приёмы за период, выдачу направлений, выполнение планов, динамику и маршруты. Список маршрутов формируется из загруженных данных и не ограничен демонстрационными услугами: в назначении можно указать врача, специальность или услугу. Клик по маршруту открывает раздел маршрутизации с фильтром по направившему врачу. Расчёты, импорт, экспорт и редактирование сохранены.

## Демо для салонов красоты

Отдельная страница: https://balakhmatov.github.io/clinic-pulse/salon/

Исходники находятся в `salon/`; интерфейс клиники в корне не меняется.

- Обзор: выручка завершённых визитов, вклад после прямых расходов, загрузка по записям, доступные окна, динамика по дням.
- Окна и записи: смены минус перерывы и занятые интервалы; длительность услуги вместе с буфером; подбор по листу ожидания, отменам и сроку повторной услуги. Предпочтения клиента, согласие на контакт, будущие записи и недавние попытки учитываются. Можно подготовить и скопировать сообщение, сохранить результат контакта, создать запись и изменить статус визита.
- Администраторы: входящие/исходящие обращения, попытки, диалоги, записи, три конверсии, доходимость наступивших визитов, заполненные часы и вклад состоявшихся визитов из окон. Повторные попытки остаются внутри одного обращения.
- Мастера: выручка, прямые расходы, вклад/час, загрузка, визиты, переделки и задержки. Возвращаемость — среди новых клиентов с истёкшим сроком повторной услуги, отдельно к мастеру и в салон. Когорта первых визитов сдвинута на 30 дней относительно выбранного периода.
- Услуги: длительность, подготовка, цена, материалы, процент мастера и интервал повторной услуги редактируются; существующие визиты сохраняют прежние условия. Вклад = цена − скидка − возврат − комиссия от чистой выручки − материалы − прочие прямые расходы. Если себестоимость неизвестна, вклад не вычисляется.
- Планы: администраторы и мастера, индивидуальные периоды, создание/изменение/удаление, факт и выполнение, адаптивный дневной темп для количественных показателей. Пересечения одинаковых планов запрещены. Проценты на дни не делятся.
- Данные: локальный импорт визитов из XLSX/CSV по шаблону, обновление по ID, Excel-отчёт, перенос всей сессии через JSON. Пустые материалы/комиссия/прочие расходы считаются неизвестными. При ошибках импорт не применяется.

Демо работает без авторизации и сервера. Данные остаются в памяти страницы и сбрасываются при обновлении; для сохранения используется JSON. Реальные рассылки и API-интеграции не подключены. Для демонстрации используйте вымышленные данные.

Проверка: `node --test core.test.mjs salon/core.test.mjs`.
